# 配置管理：在 Hydra 里管理 Claude Code 数据目录

原来的「会话迁移」页只处理桌面版 Claude.app 账号之间的会话索引。「配置管理」页把它扩展为：在 App 里浏览、阅读、迁移和整理每个 Claude Code 数据目录，不必再去 Finder 里翻文件夹。

## 数据目录

页面以「数据目录」为单位，也就是 Claude Code 的 `CLAUDE_CONFIG_DIR`：

| 位置 | 目录 | 全局配置（`.claude.json`） | 工作目录的路径 |
|---|---|---|---|
| 本机 | `~/.claude`（Windows 为 `%USERPROFILE%\.claude`） | `~/.claude.json` | 本机路径 |
| 桌面版账号 | 有独立 Claude Code 目录时为 Hydra 数据目录下的 `claude-code/<key>`，否则与本机共用 | 目录内 | 本机路径 |
| 容器账号（macOS 的 OrbStack、Windows 的 Docker Desktop） | 容器设置里的 Claude 数据文件夹 | 目录内 | 容器路径：共享文件夹在 `/workspace/<名称>` |

页面打开时先显示所有位置的卡片（按类别分组，显示会话数和最近活动时间，位置较多时可搜索）；选中后卡片收起成顶栏，与标签页同在一个卡片里，可在 Finder（Windows 为资源管理器）中打开该目录，或展开回位置列表切换。会话数只按文件名统计，不解析内容，位置再多也能很快列出。

桌面版账号另有「桌面版会话」标签页，保留原来的功能：Claude.app 侧边栏里的会话索引、导入聊天 JSON、回收站。

登录凭据（`.credentials.json`、Keychain）不会被显示、复制或导出。

## 会话

Claude Code 把每个会话存成 `projects/<编码后的工作目录>/<会话 ID>.jsonl`，旁边可能有同名的附属目录（子代理、过大的工具结果），以及 `file-history/<会话 ID>/`（用于回退文件修改的检查点）。一个会话包括这三部分，迁移、删除和导出时一起处理。

- **列表**：按工作目录分组，显示标题（自定义标题 → 自动标题 → 第一条提问）、最近活动时间、轮数、模型和大小，可搜索。只有元数据、没有对话的文件不显示。解析结果存成索引（Hydra 数据目录下的 `claude-session-index.json`），重启后照样可用：文件没变就直接用索引；只在末尾追加了内容（Claude Code 写会话的方式）就从上次读到的位置接着读；文件被重写或变短才从头读（用上次读到位置前 64 字节的摘要判断）。写到一半的最后一行留到下次再读。
- **阅读**：点会话标题，列表区域换成对话视图，返回时回到原来的滚动位置。你的消息显示为气泡；Claude 的回复按 Markdown 渲染（标题、列表、表格、代码块），由 marked 的词法分析结果直接生成 React 元素，不插入任何 HTML，会话里的网页内容和工具输出无法在 Hydra 窗口里执行代码。两条消息之间的思考和工具调用合成一个可展开的块，工具调用与结果按编号配对；Bash 显示命令，Edit 显示增删，Write 显示写入的内容，其余显示输入。链接点击时只复制，不打开：系统浏览器不走账号的代理。滚动到底时分页加载，过长的内容截断。子代理的记录和内部元数据不显示。图片（提问里粘贴的、工具结果里的截图）先只显示数量，点击后才按「第几条记录的第几张图」逐张读出，只接受 PNG、JPEG、GIF、WebP；会话里常有上百张截图，一次全读会让大会话卡住。
- **回收站**：删除的会话移到 Hydra 数据目录下的 `claude-trash/<目录 key>/`（不写进 Claude Code 自己的目录），可以恢复或彻底清空。恢复时目标已存在则拒绝，从不覆盖。
- **正在使用的会话**：30 秒内被写入过的会话不允许删除或移动，避免和正在运行的 Claude Code 冲突；复制不受限制。

### 迁移

目标可以是任何其他数据目录，支持复制和移动（复制后把原会话移入回收站）。

`claude --resume` 只列出当前工作目录下的会话，所以会话必须放到目标那一侧对应的工作目录下：

1. 先把来源的工作目录换算成 Mac 路径：容器路径 `/workspace/<名称>/…` 按该容器的共享文件夹换成 Mac 上的文件夹；Mac 路径不变。
2. 再换算到目标：目标是容器时，找包含该路径的共享文件夹（取最长匹配），换成 `/workspace/<名称>/…`；目标是 Mac 时直接使用。
3. 换算不了的（例如容器里不在任何共享文件夹下，或目标容器没有共享这个文件夹），迁移前让用户为这个工作目录选择目标：容器的 `/workspace/<名称>` 之一，或 Mac 上的文件夹。

迁移时只改写每条记录的 `cwd` 字段（在该工作目录之下的路径一并换算），对话内容原样保留：改动消息内容可能让 API 拒绝已有的思考块签名。目标里已有同 ID 的会话时跳过，从不覆盖。

### 导出为网页

阅读会话时可以导出为单个 HTML 文件：对话视图的组件在内存中渲染成静态页面，内嵌 App 自己的样式，折叠块是 `<details>`，不需要脚本就能展开；唯一的一段脚本在文件头部，用来跟随系统的深色设置。消息内容一律作为文字输出，标题也经过转义。图片内嵌进文件，总量上限 60 MB，超出的部分在页脚注明。这份文件只用于阅读和分享，不能导入；要迁移或备份，用下面的 zip。

### 导出与导入

导出为 zip：内含 `hydra-export.json`（来源位置、容器的共享文件夹、会话清单）以及与数据目录相同结构的 `projects/…`、`file-history/…`。导入时先解压到临时目录，再按与迁移相同的规则换算工作目录。

## 配置

各数据目录的配置相互独立；需要在多个账号间使用同一套配置时，用「复制到其他位置」。

- **记忆与设置**：编辑 `CLAUDE.md` 与 `settings.json`。保存前检查文件是否在外部被修改过；`settings.json` 必须是合法的 JSON 对象。原子写入，保留原文件权限。
- **技能、子代理与命令**：`skills/<名称>/SKILL.md`、`agents/**/*.md`、`commands/**/*.md`；显示名称和描述（取自 frontmatter），可以查看、编辑、删除（进回收站）、复制到其他位置（目标已有同名时询问是否覆盖）。`skills/synced` 由账号同步管理，不列出。
- **MCP 服务器**：`.claude.json` 里的用户级 `mcpServers` 与各项目的 `projects[路径].mcpServers`。环境变量和请求头的值默认隐藏。可以删除；用户级的可以复制到其他位置。修改 `.claude.json` 前建议退出该位置正在运行的 Claude Code，因为它会整体重写这个文件。
- **插件**：读取 `plugins/installed_plugins.json` 与 `settings.json` 的 `enabledPlugins`，可启用或停用。安装和卸载仍在 Claude Code 里用 `/plugin` 完成：插件记录里有绝对路径，跨 Mac 与容器复制不可靠。

## Windows

所有功能在 Windows 上同样可用（容器账号需要 Docker Desktop）：本机目录是 `%USERPROFILE%\.claude`，桌面版账号按启动器的规则判断是否有独立目录（启用了独立 Claude Code 目录，且不是默认账号或使用 Sandboxie 隔离），Sandboxie 隔离的账号的目录直通到真实磁盘。编辑文本文件时保留原文件的换行符（CRLF 或 LF）。会话从 Windows 路径迁到容器时，路径分隔符换成 `/`。
